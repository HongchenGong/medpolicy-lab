## MacBook启动

需要Node.js 24或更新的兼容版本。当前Codex环境没有系统Node，`scripts/run.sh`会自动使用已安装的Codex运行时。常规Mac安装Node.js 24后也可以用npm/pnpm。

```bash
cd "/你的项目目录"

# 当前机器已安装依赖，后续启动可跳过这一步。
./scripts/run.sh install --registry=https://registry.npmmirror.com

# 开发，默认只监听本机
./scripts/run.sh dev
```

浏览器访问 `http://localhost:3000`。停止服务按Control+C。正式持续使用时建议构建后启动：

```bash
./scripts/run.sh build
./scripts/run.sh start
```

原开发环境的数据已初始化，无须重复操作。新克隆的仓库需要私密初始化配置后才能建立12个账号。关闭浏览器或重启服务不会删除数据。不要删除 `data/`，也不要在服务运行期间手工替换数据库文件。

## 在新的机器创建12个账号

```bash
./scripts/run.sh install --registry=https://registry.npmmirror.com
cp .env.example .env
./scripts/run.sh init --force-password-change
```

初始化会交互式要求设置并确认**独立的管理员密码（至少12位，输入不回显）**。普通成员初始密码为私密初始化配置中指定的密码，只在服务端哈希后保存，不出现在前端或公开接口。学号全程为字符串。

如果在无交互终端初始化，可以安全生成管理员随机密码：

```bash
./scripts/run.sh init --generate --force-password-change
```

随机密码仅写入数据目录下0600权限的本机文件，不打印到终端。不要将此文件或数据库公开分享。已有账号时初始化会拒绝执行，不会重置现有密码或覆盖历史。

| 姓名 | 登录学号 | 初始模块 |
|---|---|---|
| 组长 | 私密初始化配置提供 | 无，项目管理员 |
| 11位成员 | 私密初始化配置提供 | R01—R11 |

成员在“账号与安全”修改密码，至少10位；组长可安全重置成员密码或停用账号。改密、重置与停用均撤销已有会话。连续5次登录失败会暂停该学号15分钟；同一受信任来源15分钟最多120次尝试。

## 让11名同学访问

### 同一局域网临时协作

在Mac和同学设备处于可互通的同一网络时运行：

```bash
./scripts/run.sh exec next start --hostname 0.0.0.0 --port 3000
```

先执行过build。到macOS“系统设置 → 网络”查看本机局域网IP，同学访问 `http://你的局域网IP:3000`。按macOS提示允许本地网络访问。Mac需要保持开机、联网并关闭自动睡眠；校园网若开启终端隔离，设备可能无法互访。未设置APP_ORIGIN时会按实际HTTP Host做同源校验；如果设置了APP_ORIGIN，所有人必须使用该同一地址。

局域网HTTP适合可信网络临时试用。供不同网络长期协作，应部署到有HTTPS的校内服务器或中国大陆可访问服务器。`localhost`不是同学可直接访问的公网地址。实际云端部署状态以本次任务的验证结果为准。

### 正式协作部署

本地模式面向**一个应用实例 + 本机SQLite持久化磁盘 + 上传目录**，适合本项目12人短周期协作。无须购买独立数据库服务。不要用临时文件系统、无持久磁盘的函数托管、多副本容器或NFS共享SQLite。已增加PostgreSQL与私有对象存储适配，免费云端部署见 docs/cloud-deployment.md。

需自行准备：

1. 可供同学访问的服务器（校内或自行选择的国内云服务器）、Node.js 24、持续运行的进程服务。
2. 持久化磁盘；实际容量取决于附件数量，单文件最多20MB。导出ZIP使用内存打包，资料接近GB级时应提高服务器可用内存或减少单个附件体积。
3. 域名/DNS、HTTPS证书及反向代理。`deploy/nginx.conf.example`是待替换域名和证书路径的示例。
4. 设置精确的 `APP_ORIGIN=https://你的域名` 与 `COOKIE_SECURE=true`。只有经过自己配置且覆盖X-Real-IP的反向代理，才设置 `TRUST_PROXY=true`。
5. 定期备份、磁盘容量监测，开放必要端口；应用3000端口留在回环地址，文件目录不由Nginx直接公开。
6. 与学校/接入商确认上线备案手续。中国境内非经营性互联网信息服务的备案要求可查[通信管理局办事指南](https://ynca.miit.gov.cn/bsfw/bszn/art/2020/art_1e2c69c668b74b59b2572d2a8138b454.html)；不能假定一周内一定办结。

可选Docker模板已提供，但本次未在Docker守护进程中实际运行。模板使用独立命名数据卷，**不会自动读取当前Mac的data目录**。新环境先构建，再初始化：

```bash
docker compose build
docker compose run --rm medpolicy pnpm run init --force-password-change
docker compose up -d
```

容器内没有Chrome，不运行浏览器测试。国内构建可通过 `NPM_REGISTRY=https://registry.npmmirror.com` 指定依赖镜像；镜像获取方式由你的服务器环境决定。

## 成员怎么交材料

1. 学号登录后直接进入“我的研究模块”；首次改密后查看目的、问题、交付要求、课程资料及截止时间。
2. 填写摘要与2—3条真实参考来源。正文可在线填写（至少600字，建议约1000字），或上传DOCX/PDF。Excel为补充附件，不能单独替代核心文档。
3. 一次最多5个附件，每个20MB以内。支持DOCX、XLSX、PPTX、PDF、PNG、JPG、TXT、CSV、MD。
4. 写清本次修改说明与本次工时，提交生成V1；修改后再次提交生成V2、V3等。**重新提交需选择新版本包含的全部附件**，上一版不会自动合并。
5. 在“审核与版本”查看评分变化、具体意见与历史原件。通过或冻结后不能直接修改，需组长重新开放再交新版本。

应用校验扩展名、文件签名、Office结构、宏/ActiveX、附件数量与体积，并强制授权下载；这不是完整杀毒引擎。下载文件由本地Office/PDF应用打开。本版未实现网页内Office编辑器或Word/PDF在线预览。

## 组长怎么审核

在“审核中心”下载研究原件 → 到自己的ChatGPT项目中对应成员对话审核 → 回到网站“录入评分与审核”。手工填写六项分数、主要问题、修改意见，可粘贴反馈原文或附加反馈文件；选择退回/重做或审核通过。网站自动合计100分量表，85分及以上显示“建议终审”，不会自动决定通过。

已通过版本可以冻结；重新开放只允许创建新版本，旧批准版本、作者和评分保持不变。管理员只能审核最新提交，避免新版本提交后误批准旧文件。

教师原始规则完整保留：六维各20分、合计120分，是否折算待确认；个人成绩“小组得分×80%＋个人贡献×20%”。内部审核分数和互评分数不换算为正式课程成绩。

## 分工、进度与甘特图

- 研究模块“调整负责人”会自动交换两人的模块，分配记录保存在独立assignments表。原文件、贡献和历史评分始终归实际提交人。
- “编辑任务”可改标题、问题、交付要求、日期、优先级和预计工时；可添加/删除子任务。
- 甘特图按数据库日期绘制，支持负责人、状态和模块编号/主题筛选；点击条形打开模块，组长点任务旁设置按钮改日期。
- 成员可更新自己模块的0—90%工作进度和累计实际工时，审核通过才变为100%。仪表盘完成率为“已通过或冻结模块数 / 可见模块数”，不按文件数量计算。
- 项目状态每15秒刷新一次，也可手动刷新。逾期以当前截止时间与有效状态判断；提交是否按时使用提交当时截止时间记录，之后延期不重写历史。
- 所有界面时间固定为北京时间；数据库保存UTC时间。11月3日14:00仅为下午汇报的倒计时暂定时刻，组长可编辑里程碑。
- R11保留10月30日18:00独立框架初稿与10月31日综合补充的分阶段要求，不承担替别人重新研究。

## 课程资料、贡献与互评

- 资料库按教师PPT、作业要求、教材、官方政策、其他资料分类。组长可控制是否向成员公开，并关联模块；模块关联用于检索，不限制已公开课件的下载。
- 本机资料可用 `./scripts/run.sh import:course /课程资料文件夹` 导入；按哈希防止重复导入。已读取课件的依据见 `docs/course-notes.md`。
- “成员与贡献”按原作者统计提交次数、按时提交、回应反馈、自报工时与通过版本。组长可单独记录自己的网站维护、协调、审核、PPT整合和课堂汇报贡献。
- 组长开启互评后，成员可对其他成员（含组长）各提交一次1—5分与文字评价，不能自评。结果仅管理员汇总；可导出真实XLSX。

## 最终批量导出

“资料打包导出”会检查11个模块的**最新版本**都已审核通过或冻结。点击“冻结并导出全部已审核材料”后，将通过版本冻结，并生成：

```text
MedPolicyLab_Final/
  R01_最终版本原提交人/
    原始文件（以短文件ID前缀避免重名，原名在清单中保留）
    Research_Summary.md
    Sources.md
  ... R11_最终版本原提交人/
  References/
  Presentation_Brief.md
  Submission_Manifest.csv
```

清单包含姓名、模块、原始文件名、状态、版本、摘要、来源、学号、时间与SHA256。仅在线提交时正文保存在Markdown中。Word文件不转码，原始字节保持不变。

未全部通过时仍可下载“现有全部版本工作包”。汇报提示词可单独下载，明确后续在ChatGPT/Canva制作12—15页PPT、图表、互动、逐页讲稿、演讲者备注与最终PPTX。

## 备份与恢复

```bash
./scripts/run.sh backup
```

脚本使用SQLite在线备份API生成一致的数据库快照，然后复制不可变上传文件。不要在运行中只复制sqlite主文件而忽略WAL。恢复时停止应用，将备份中的 `medpolicy.sqlite` 和 `uploads/` 放进**新的空数据目录**，设置DATA_DIR后启动。验证账号、资料和提交后再切换服务。备份不包含管理员初始密码明文文件。

## 项目结构与实现边界

```text
app/                    Next.js路由、样式和唯一API分发入口
components/workspace.tsx 工作台和各功能页面
lib/catalog.ts          11个模块、成员名单、评分量表与默认里程碑
lib/db.ts               数据模型、约束、事务和操作日志
lib/auth.ts             scrypt密码哈希、服务端会话、CSRF及权限
lib/files.ts            受控上传、内容检查、持久文件与下载授权
lib/api.ts              各工作流接口和服务器端校验
lib/export.ts           ZIP、CSV、XLSX及最终汇报提示词
scripts/                初始化、课件导入、备份和启动助手
tests/                  真实数据库验收及真实浏览器测试
data/                   SQLite与原始文件（不入库、不公开）
deploy/                 Nginx配置示例
```

P0全部实现。P1已实现互评/XLSX汇总、贡献工时统计、版本评分比较、提示词与日志导出；未实现在线Word/PDF预览和复杂工时图表。没有实时聊天、AI评分、RAG、自动PPT或Canva集成，符合本项目边界。

技术参考：[Next.js路由与会话Cookie](https://nextjs.org/docs/app/api-reference/functions/cookies)、[SQLite在线备份](https://www.sqlite.org/backup.html)。
